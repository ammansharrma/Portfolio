# v2 Phase 2 — Loader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Commit policy override:** stays fully uncommitted until the project owner explicitly says to commit. Implementers do **not** run `git commit` or `git add`. Task review diffs are generated by snapshotting each task's target files before dispatch and diffing the snapshot against the post-task file (`diff -u`), **not** `git diff HEAD` — Phase 1 hit a false-positive review finding from comparing against the distant, multi-phase-old `HEAD` instead of "state right before this task." See the ledger for the incident.

**Goal:** Replace the static 9-dot loader with the pixel-dissolve "A" mark assembly sequence from the spec — the mark builds itself from a field of dots, a live-seam fact types out, and the whole thing dissolves into Hero.

**Architecture:** All changes are contained to `src/components/Loader.jsx` and `src/components/Loader.css` — no other file imports either beyond `App.jsx`'s existing `<Loader />` usage, which is unaffected (same props contract: `onLoadComplete`). One deliberate scope cut, recorded here rather than silently dropped: the spec's "pointer-reactive dot grid" (§14 #4) is **not** built in this phase. Real-time cursor-proximity tracking is a materially bigger, riskier piece of engineering than the mosaic-assemble sequence that's the actual signature moment here, and #4 is *also* explicitly scoped to Hero's background in Phase 6 (global polish) — building it twice, once here and once there, is wasted work. This phase ships the ambient dots as a simple looping idle drift (CSS keyframes, no JS mouse-tracking); Phase 6 is where pointer-reactivity gets built once and can be applied to both the Loader field and Hero's background together.

**Tech Stack:** React 18, `motion/react` (already a dependency), plain CSS keyframes for the ambient drift. No automated test suite — verification is `npm run build` plus manual visual confirmation via `npm run dev`.

**Spec:** [docs/DESIGN_SPEC.md](../../DESIGN_SPEC.md) — §15 (Loader wireframe/sequence).

## Global Constraints

- The existing `sessionStorage` "seen" skip (`Loader.jsx:4-13`, `shouldSkipLoader`/`markSeen`) keeps working exactly as before — this phase changes what plays *during* the loader, not whether/when it shows.
- Skip must stay instant — no fade-out delay on the manual skip path, only on the natural end-of-sequence path.
- Total natural-sequence duration budget: ~1.4s before the loader would naturally start dissolving (spec's stated ceiling) — the existing 900ms constant was a flat delay; this phase's sequence needs more room to actually play out its steps and is documented per-step below, so the top-level timer moves from 900 to 1400.
- **Reduced motion is already fully handled and stays that way — this phase adds no new reduced-motion branches.** `shouldSkipLoader()` (`Loader.jsx:6-13`) checks `prefers-reduced-motion: reduce` first; when it matches, `visible` starts `false` and the component returns `null` before any of this phase's new markup (bitmap, field, live-seam line) ever renders — the whole loader is skipped, straight to Hero. None of Tasks 1–3's new elements need their own `@media (prefers-reduced-motion: reduce)` CSS or a `reduceMotion` JS flag, because reduced-motion users never reach code that renders them. Do not add such branches — they would be unreachable dead code.
- No new npm dependency.

### Task 1: "A" mark — dot-matrix bitmap + mosaic assemble

**Files:**

- [ ] **Step 1: Define the "A" bitmap and replace the plain-text mark**

The current `.loader-mark` (`Loader.jsx:50`, `<p className="loader-mark">A</p>`) renders the letter as plain text. Replace it with a 7-row × 5-column dot-matrix bitmap of the same letter, built from a hardcoded boolean grid — not a font, so it can assemble cell-by-cell:

```
row 0: . █ █ █ .
row 1: █ . . . █
row 2: █ . . . █
row 3: █ █ █ █ █
row 4: █ . . . █
row 5: █ . . . █
row 6: █ . . . █
```

In `Loader.jsx`, add above the `Loader` function:

```jsx
// 7x5 bitmap of the "A" mark, row-major, true = filled cell.
const A_BITMAP = [
  [false, true, true, true, false],
  [true, false, false, false, true],
  [true, false, false, false, true],
  [true, true, true, true, true],
  [true, false, false, false, true],
  [true, false, false, false, true],
  [true, false, false, false, true],
];

// Flat index (row * 5 + col) of every filled cell, in a fixed hand-picked
// order that dissolves the mark in rather than filling row-by-row.
const A_FILL_ORDER = [17, 3, 21, 1, 33, 8, 26, 2, 15, 20, 31, 6, 11, 30, 16, 25, 5, 32];
```

(`A_FILL_ORDER` has exactly 18 entries — one per filled cell in the 7×5 grid above; verify this by counting `true` values in `A_BITMAP` if you change the bitmap.)

- [ ] **Step 2: Render the bitmap as a CSS grid of cells**

Replace `<p className="loader-mark">A</p>` with:

```jsx

        {A_BITMAP.flat().map((filled, i) => {
          const fillStep = A_FILL_ORDER.indexOf(i);

              key={i}
```

Keep the visually-hidden accessible label — add right after the closing `</div>` of `loader-mark-grid`:

### Task 3: Live-seam line + total sequence timing

**Files:**
- Modify: `src/components/Loader.jsx`
- Modify: `src/components/Loader.css`

**Interfaces:**
- Consumes: none new. Deliberately does **not** import anything from `Hero.jsx` — `useTypewriter` there is a local, unexported hook; extracting it into a shared module is a refactor of already-shipped, already-reviewed code that's out of scope for this task. This task writes a small, local, one-shot typing effect instead (types once, doesn't cycle or delete — the loader is on screen for about a second, cycling multiple facts doesn't fit).

- [ ] **Step 1: Add a one-shot typing effect**

In `Loader.jsx`, add above the `Loader` function (after `A_FILL_ORDER`):

```jsx
const LIVE_FACT = 'role: Member of Technical Staff · company: Mindstix · since: Aug 2024';

function useTypeOnce(text, startDelayMs) {
  const [charCount, setCharCount] = useState(0);

  useEffect(() => {
    let intervalId;
    const startId = window.setTimeout(() => {
      intervalId = window.setInterval(() => {
        setCharCount((c) => {
          if (c >= text.length) {
            window.clearInterval(intervalId);
            return c;
          }
          return c + 1;
        });
      }, 18);
    }, startDelayMs);

    return () => {
      window.clearTimeout(startId);
      window.clearInterval(intervalId);
    };
  }, [text, startDelayMs]);

  return text.slice(0, charCount);
}
```

(No `reduceMotion` parameter — per the Global Constraints, reduced-motion users never render this component at all, so this hook only ever needs to handle the animated path.)

- [ ] **Step 2: Render the live-seam line and update the total timer**

In the `Loader` function, add the hook call and render the line. The mark finishes assembling at ~810ms (18 cells × 45ms stagger) + 280ms fill duration ≈ 1090ms; start the live-seam typing at 900ms so it begins just before the last cells land, reading as continuous rather than two separate beats:

```jsx
function Loader({ onLoadComplete }) {
  const [visible, setVisible] = useState(() => !shouldSkipLoader());
  const liveText = useTypeOnce(LIVE_FACT, 900);

  useEffect(() => {
    if (!visible) {
      onLoadComplete?.();
      return undefined;
    }

    const timer = window.setTimeout(() => {
      markSeen();
      setVisible(false);
      onLoadComplete?.();
    }, 1400);

    return () => window.clearTimeout(timer);
  }, [visible, onLoadComplete]);

  // ... rest unchanged
```

(This replaces the existing `useEffect`'s `900` timeout with `1400` and adds the `liveText` line above it — everything else in the function body, including `shouldSkipLoader`'s reduced-motion check and the `if (!visible) return null;` guard, is untouched.)

Add the live-seam paragraph as the last child inside `.loader`, before the skip button:

```jsx
      <p className="loader-live font-mono" aria-live="off">
        <span className="loader-live-prefix">{'›'}</span> {liveText}
        <span className="loader-live-cursor">{'▮'}</span>
      </p>
```
